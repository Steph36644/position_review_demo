## 二、核心用户故事

### US-1：维护我的标的主数据（行业/风格/ETF 成分股）

**作为**我自己，**当**我开始使用 v1.3 或新增持仓时，**我希望**为每只持仓标的填写行业、风格、市场、是否 ETF 及 ETF 前十大成分股，
**以便**系统能据此做行业/风格切片与重叠检测。

**验收路径**：持仓卡片"主数据"入口 → 编辑弹窗填写 5 字段 → 保存 → 切片与重叠检测立即按新数据重算

### US-2：一眼看穿我的持仓在行业上是否真的分散

**作为**我自己，**当**盘后复盘查看持仓时，**我希望**在持仓环形图区域切换到"行业"Tab，看到各申万一级行业的市值占比饼图与条形图，
**以便**我发现"8 只票里 5 只都是电力设备"这种伪分散。

**验收路径**：看板持仓环形图 → 切"行业"Tab → 饼图+降序条形图 → 占比合计=总市值

### US-3：发现 ETF 与个股之间的隐形重叠

**作为**我自己，**当**我同时持有科创50 ETF 和科创半导个股/ETF 时，**我希望**系统提醒我两者成分股重叠度超过 15%，
**以便**我意识到"看似分散实则同涨同跌"的风险。

**验收路径**：看板 → 重叠检测面板 → 两两重叠矩阵 → 科创50↔科创半导行橙色高亮+重叠度数值

### US-4：调仓前预演对整体仓位的影响

**作为**我自己，**当**我打算买入某只标的或加仓时，**我希望**在 What-If 抽屉里输入拟交易（标的/方向/数量/价格），实时看到交易后总仓位、单标的占比、行业占比及是否触发告警，
**以便**我在执行前就知道这笔交易会不会让仓位超带、单标的超限、某行业超限。

**验收路径**：看板"What-If 预演"按钮 → 抽屉输入拟交易 → 实时输出前/后对比（水位仪表+占比表+告警项）→ 决定是否执行（执行后走交易录入流，工具不下单）

### US-5：行业超限时被醒目提醒

**作为**我自己，**当**某行业市值占比超过我设定的 `single_industry_max` 时，**我希望**顶部告警横幅出现"XX行业 占比 35%，超过单行业上限 30%"，
**以便**我在复盘时第一时间处理集中度风险。

**验收路径**：录入持仓 → 横幅出现行业告警 → 查看跳转至行业切片 → 今日忽略留痕

## 三、功能详细需求

### 3.1 DAQ-4 标的主数据手动维护

#### 3.1.1 功能描述

为每只标的（持仓中出现过的 name）维护主数据，作为 D1/D2/D4 切片与重叠检测的数据基础。主数据以 `name` 为主键，与持仓/交易流水的 name 关联。无接口环境下，仅靠手动维护即可完整跑通全部 v1.3 功能。

#### 3.1.2 字段定义（对应 v1.0 第八章 DB.instruments）

| 字段          | 类型        | 必填                | 取值/约束                                   | 含义                    |
| ----------- | --------- | ----------------- | --------------------------------------- | --------------------- |
| name        | string    | 是                 | 与 holdings/trades 的 name 完全一致           | 标的名称（主键）              |
| industry    | string    | 是                 | 申万一级行业名称；港股填恒生行业分类；ETF 填"指数基金"或跟踪指数所属行业 | 行业分类                  |
| style       | string    | 是                 | 枚举：红利/成长/价值/周期/主题                       | 风格标签                  |
| market      | string    | 是                 | 枚举：沪/深/港/美                              | 所属市场                  |
| is\_etf     | boolean   | 是                 | true/false                              | 是否 ETF                |
| etf\_top10  | string\[] | is\_etf=true 时建议填 | 成分股名称数组（≤10），名称需与其他 holdings name 口径一致  | ETF 前十大成分股（仅 ETF 有意义） |
| updated\_at | string    | 否                 | ISO                                     | 最后更新时间                |

**口径说明**：

- **industry**：A 股用申万一级（如"电力设备""医药生物"）；港股用恒生行业分类（如"资讯科技业"）；ETF 可填"指数基金"或其跟踪指数的代表性行业（如科创50 填"电力设备/半导体"）——以用户对该 ETF 风险暴露的判断为准。
- **style**：5 类互斥标签，单选。
- **etf\_top10**：仅用于 D4 重叠检测；填得越准重叠检测越准，填不全则交集可能偏小（不会误报，只会漏报）。非 ETF 该字段为 `[]`。

#### 3.1.3 交互流程

```
[入口] 持仓卡片右上角"主数据"按钮 + 看板顶部"标的主数据"批量入口
   ▼
标的主数据编辑弹窗
   ├─ 顶部：标的名称（下拉选择当前持仓标的，或手动输入新增）
   ├─ industry：下拉（常用申万一级预置 + 可手动输入自定义）
   ├─ style：单选按钮组（红利/成长/价值/周期/主题）
   ├─ market：单选（沪/深/港/美）
   ├─ is_etf：开关
   ├─ etf_top10：仅 is_etf=true 时显示，标签式输入（回车添加，×删除）
   └─ [保存] → 校验 industry/style/market 必填 → 写入 DB.instruments
   ▼
即时生效：D1/D2 切片、D4 重叠检测、DAA-3 行业告警立即按新主数据重算
```

#### 3.1.4 边界条件

- **首次使用无 instruments**：持仓卡片显示"未设置主数据"黄色提示，点击直达编辑弹窗；切片将该标的归入"未分类"组。
- **存量持仓未补录**：D1/D2 切片中显示"未分类"分组并标注数量，引导用户补录。
- **name 不一致**：instruments 的 name 必须与 holdings/trades 的 name 完全匹配（含空格、大小写）；编辑弹窗的标的下拉来源于持仓中出现过的 name 集合，避免手动输入不一致。
- **ETF 成分股 name 与持仓 name 口径**：用户需自行保证成分股名称与持仓中标的名称一致（如持仓写"中芯国际"，成分股也写"中芯国际"）；系统不做模糊匹配（PRD §1.4 永久不做智能识别）。

#### 3.1.5 DAQ-5 接口辅助（可选增强，非必须路径）

- 提供"从接口预填"按钮：输入标的代码，调用免费接口（东方财富 F10 成分股接口）获取行业与前十大成分股，填入表单但**不落库**，用户确认后保存。
- 接口失败或返回数据异常时，提示"接口获取失败，请手动填写"，不阻塞 DAQ-4 手动路径。
- 本功能为增强项，若时间紧张可延后实现；DAQ-4 手动路径必须独立可用。

### 3.2 D1 行业切片（DAA-5 行业维度）

#### 3.2.1 功能描述

将看板持仓环形图区域改造为维度切换 Tab（标的/行业/风格），行业 Tab 按 `instruments.industry` 聚合各未清仓标的的市值，输出饼图 + 降序条形图，占比合计 = 总市值。

#### 3.2.2 计算口径

```
行业分组 = group by instruments.industry（未匹配 → "未分类"）
各行业市值 = Σ 组内未清仓标的 h.market_value
行业占比   = 行业市值 / overview.total_assets × 100%    （分母为总资产，与单标的占比口径一致）
合计校验   = Σ 各行业占比 + 现金占比 = 100%
```

- 已清仓标的（h.cleared=true）不参与切片。
- 现金占比单独显示在条形图末尾（不进饼图）。

#### 3.2.3 展示规格

```
┌─────────────────────────────────────────────┐
│ 持仓结构 [标的] [行业] [风格]               │
│  ┌─────────┐  电力设备  45.2% ████████████   │
│  │  饼图    │  医药生物  18.5% ███████        │
│  │  (行业)  │  指数基金  12.0% █████          │
│  └─────────┘  未分类    6.3%  ██             │
│               现金      18.0% ██████         │
└─────────────────────────────────────────────┘
```

| 元素     | 规则                                                |
| ------ | ------------------------------------------------- |
| Tab 切换 | 标的（默认，v1.2 既有环形图）/ 行业 / 风格，切换时复用同一 Chart.js 实例改数据 |
| 饼图     | 各行业占比；"未分类"用灰色；点击扇区可下钻显示该行业下的标的明细                 |
| 条形图    | 各行业占比降序，超 `single_industry_max` 的行红色高亮            |
| 占比合计   | 饼图下方显示"合计 82.0% + 现金 18.0% = 100%"勾稽校验            |
| 下钻     | 点击条形图行或饼图扇区，展开该行业的标的列表（name + 市值占比）               |

#### 3.2.4 边界条件

- 无 instruments 数据：全部标的归入"未分类"，条形图仅一行。
- 总资产缺失：显示「—」+「请先录入当日持仓」。
- 行业数 > 8：饼图自动合并尾部小占比行业为"其他"（阈值 <2%），条形图仍全部展示。

### 3.3 D2 风格切片（DAA-5 风格维度）

#### 3.3.1 功能描述

与 D1 同构，按 `instruments.style` 聚合市值占比。5 类风格固定枚举：红利/成长/价值/周期/主题。

#### 3.3.2 与 D1 的差异

- 分组维度为 style 而非 industry。
- 风格标签颜色固定：红利=橙、成长=红、价值=蓝、周期=灰、主题=紫（便于跨日对比风格漂移）。
- 不触发告警（无 single\_style\_max 参数，见 D-v1.3-4）。

#### 3.3.3 边界条件

- 同 D1；未分类归入"未设置风格"。

### 3.4 D4 ETF 重叠检测（DAA-6）

#### 3.4.1 功能描述

检测持仓中 ETF 与 ETF、ETF 与个股之间的成分股重叠，重叠度 >15% 时醒目提醒，让"同涨同跌"的隐形集中暴露。

#### 3.4.2 计算口径

```
对于持仓中每对组合 (A, B)，A 是 ETF 或 B 是 ETF：
  成分股集合 S_A = A.etf_top10（若 A 不是 ETF，则 S_A = {A.name}）
  成分股集合 S_B = B.etf_top10（若 B 不是 ETF，则 S_B = {B.name}）
  交集 C = S_A ∩ S_B
  重叠度 = |C| / min(|S_A|, |S_B|) × 100%     （按成分股数量占比，简单口径）
  重叠度 > 15% → 标记提醒
```

- **为什么用数量占比而非市值占比**：etf\_top10 无权重数据（DAQ-4 仅存名称），用数量占比是信息不足下的合理近似；若后续 DAQ-5 接口能取到权重，可升级为市值加权。
- **ETF↔个股**：个股自身视为单元素集合 {name}，若该 name 出现在某 ETF 的 top10 中，则重叠度 = 1/min(1,10)=100%，必然触发提醒（这正是"个股被 ETF 重仓"的暴露）。
- **两两矩阵**：N 个持仓生成 N×N 矩阵，只展示上三角（A\<B）且至少一方是 ETF 的组合。

#### 3.4.3 展示规格

```
┌──────────────────────────────────────────────────────┐
│ ETF 重叠检测                                    [刷新] │
```

### 3.5 P1-4 What-If 交易预演（DAA-7）

#### 3.5.1 功能描述

侧边抽屉输入拟执行交易（标的/方向/数量/价格），系统在**当前持仓快照上叠加该交易**，实时输出交易后的总仓位、单标的占比、行业占比、水位状态与告警项，全部**只读不落库**。用户据此决定是否执行；执行后走正常交易录入流。

#### 3.5.2 模拟交易输入

| 字段     | 类型     | 约束                  | 含义      |
| ------ | ------ | ------------------- | ------- |
| name   | string | 当前持仓标的或新标的          | 拟交易标的   |
| action | enum   | buy/add/sell/reduce | 方向      |
| amount | number | >0 整数               | 数量（股/份） |
| price  | number | >0                  | 价格      |

- **买入新标的**：name 不在当前持仓中，模拟新增持仓。
- **加仓**：name 在持仓中，模拟增加数量与市值。
- **卖出/减仓**：name 在持仓中，模拟减少数量；若模拟后数量≤0，视为清仓。
- **价格**：用于计算交易金额 = amount × price；买入增加市值、卖出减少市值（简化：不考虑滑点与手续费）。

#### 3.5.3 模拟计算逻辑（DAA-7）

```
输入：当前 holdings[date]、overview[date]、plan、拟交易 T
1. 克隆当前持仓快照为 simulated_holdings（深拷贝，不修改原数据）
2. 对 T 应用交易：
   - buy/add：若 name 存在 → position += amount，cost 加权平均，current_price=T.price
               若 name 不存在 → 新增持仓 {name, position:amount, cost:T.price, current_price:T.price, market_value:amount×T.price}
   - sell/reduce：position -= amount；若 position ≤ 0 → cleared=true, market_value=0
   - 更新 market_value = position × current_price
3. 重算 simulated_overview：
   - market_value = Σ simulated_holdings.market_value
   - total_assets 不变（现金随交易变化：买入减现金、卖出现金加回）
     cash_change = (sell/reduce ? +1 : -1) × amount × price
     simulated_total_assets = total_assets  （总资产不变，内部现金↔市值转换）
     注：仓位% = market_value / total_assets，现金变化已体现在 market_value 变化中
4. 调用 AlertService.calcWaterLevel(simulated_overview, plan) → 交易后水位
5. 调用 AlertService.evaluateAlerts(simulated_overview, simulated_holdings, plan) → 交易后告警（含行业维度）
6. 调用 DAA-5 行业切片(simulated_holdings, plan) → 交易后行业占比
7. 输出前/后对比
```

#### 3.5.4 展示规格（侧边抽屉）

```
┌──────────────────────────────────────────────────────┐
│ What-If 交易预演                              [关闭] │
├──────────────────────────────────────────────────────┤
│ 拟交易：                                              │
│ 标的 [科创50 ▾] 方向 [买入 ▾] 数量[____] 价格[____]   │
│                              [计算]  [清空]           │
├──────────────────────────────────────────────────────┤
│ 交易前 → 交易后                                        │
│ 总仓位：82.3% → 87.5%  （水位：带内 → 高于上限 ⚠）     │
│ 单标的占比：科创50 12% → 18%  （单标的上限 25% ✓）     │
│ 行业占比：电力设备 45% → 52%  （行业上限 30% ⚠ 超限）   │
│                                                       │
│ 触发告警：                                             │
│  ├─ 总仓位 87.5% 超出上限 80%（+7.5pp）                 │
│  └─ 电力设备 占比 52% 超过单行业上限 30%                │
│                                                       │
│ [去执行此交易] → 跳转交易录入弹窗（预填参数）           │
└──────────────────────────────────────────────────────┘
```

| 元素    | 规则                                                                       |
| ----- | ------------------------------------------------------------------------ |
| 实时计算  | 输入任一字段后自动重算（防抖 300ms），无需点"计算"按钮                                          |
| 前/后对比 | 关键指标双列展示，变化项用箭头↑↓与颜色（恶化红、改善绿）标注                                          |
| 水位仪表  | 复用水位渲染组件，展示"交易后水位"（色带按 plan）                                             |
| 告警项   | 复用 AlertService 判定，展示交易后新增/加剧的告警项（不写入 ignored\_alerts）                   |
| 去执行   | 点击跳转 R1/R2 交易录入弹窗并预填参数；用户确认保存后才落库，What-If 本身不写任何业务数据                     |
| 不落库铁律 | What-If 全部计算基于深拷贝的 simulated\_\*，不修改 DB.holdings/overview/trades/reviews |

#### 3.5.5 边界条件

- 卖出数量 > 持仓数量：提示"卖出数量超过持仓 X 股"，不计算。
- 买入新标的无 instruments：行业占比归入"未分类"，提示"该标的未设置主数据，行业占比可能不准"。
- 总资产缺失：无法计算，显示"请先录入当日持仓"。
- 多笔预演：本版支持单交易预演（一次输入一笔）；多笔组合预演 → v2.x 或后续增强。

### 3.6 DAA-3 行业维度告警启用（增量）

#### 3.6.1 功能描述

v1.2 已存储 `single_industry_max`（默认 30%）但未参与判定。v1.3 在 `DIM_EVALUATORS` 注册表中追加 `industry` 评估器，当任一行业市值占比 > single\_industry\_max 时触发告警，复用 P1-3 横幅、跳转、忽略机制。

#### 3.6.2 判定规则

```
行业占比 = 该行业全部未清仓标的市值之和 / total_assets × 100%
若 行业占比 > single_industry_max → 触发告警
告警文案："XX行业 占比 35.2%，超过单行业上限 30%"
target = {type:'slice', anchor: industry}   → 跳转至行业切片 Tab 并高亮该行
```

- 边界：恰等于上限 → 不告警（闭区间，与 v1.2 单标的/水位口径一致）。
- "未分类"行业也参与判定（若未分类占比超限同样告警，倒逼补录主数据）。

### 5.3 关键交互铁律

1. **What-If 不落库**：全部计算基于深拷贝，禁止修改任何 DB.\*；"去执行"按钮仅跳转预填，不自动保存。
2. **主数据即时生效**：instruments 保存后，切片/重叠/行业告警立即重算，无需刷新。
3. **切片占比勾稽**：行业/风格占比合计 + 现金 = 100%，UI 显示勾稽校验值。
4. **重叠检测不阻塞**：ETF 成分股缺失时跳过该标的并提示，不报错。
5. **行业告警复用机制**：与 v1.2 单标的/水位/现金告警同一横幅、同一忽略机制、同一失效规则。
6. **name 一致性**：instruments 的 name 从持仓 name 集合中选择，禁止手动输入（避免关联失败）。
