## 二、技术栈选型

**沿用 v1.2.3 全部选型，零新增依赖。**

| 层次 | 选型 | 说明 |
|---|---|---|
| 前端框架 | 原生 JavaScript（ES6+，IIFE + `App` 命名空间） | 沿用 |
| UI 样式 | Tailwind CSS（CDN） | 沿用 |
| 图表 | Chart.js 4.x（CDN） | **复用**：切片饼图/条形图复用 v1.2 已有 pieChart 实例，切换维度改数据不重建 |
| 存储 | localStorage（结构化）+ IndexedDB（截图） | 沿用；新增 `pr2_instruments` key |
| 构建/部署 | 无构建，纯静态 | 沿用 |

**关键决策**：

- **决策 1：切片 Tab 复用单一 Chart.js 实例**。v1.2 已有 `pieChart` 与 `barChart` 实例管理；v1.3 维度切换时仅调用 `chart.data = newData; chart.update()`，不销毁重建，避免内存泄漏与动画卡顿。
- **决策 2：What-If 用深拷贝构造模拟快照，不引入状态管理**。单次预演为同步纯计算（<10ms），`structuredClone` 或 JSON 深拷贝 holdings/overview 后应用交易，再调用既有 AlertService/PortfolioSliceService 纯函数。
- **决策 3：重叠度用成分股数量占比而非市值占比**。DAQ-4 仅存 etf_top10 名称（无权重），数量占比是信息不足下的合理近似；接口签名预留 weight 字段，若未来 DAQ-5 获取权重可升级。
- **决策 4：行业告警复用 v1.2 DIM_EVALUATORS 注册表**。v1.2 alertService.js 已注释"v1.3 追加 industry/style 即可"，本版直接在 `DIM_EVALUATORS` 中注册 `industry` 评估器，`single_industry_max` 从 plan 读取（v1.2 已存储）。

**新增模块与既有模块的关系**：

- `InstrumentService`：instruments 的读取/校验/保存/默认值。被 PortfolioSliceService、EtfOverlapService、WhatIfService 三方共享（单源）。

- `WhatIfService`（纯函数）：输入 = 当前快照 + plan + 拟交易；输出 = 模拟后的 waterLevel/alerts/slices。被 WhatIfController 调用，**不调用任何 Repository 写方法**。
- `AlertService` 扩展：`DIM_EVALUATORS.industry` 评估器调用 `PortfolioSliceService.groupBy('industry')` 后逐组比较 `single_industry_max`。

### 4.4 计算口径（与 PRD §3.2.2 一致，全产品唯一实现于 PortfolioSliceService）

```javascript
// 通用分组聚合

  // holdings: 当日未清仓持仓
```

## 五、核心模块设计

### 5.1 InstrumentService（DAQ-4）

```typescript
getInstruments(): {[name]: Instrument}        // 读取全部
getInstrument(name): Instrument | null         // 读取单只
getAllHoldingNames(): string[]                 // 从持仓+交易中收集所有出现过的 name（供下拉选择）
```

- `getAllHoldingNames`：遍历 `db().holdings[all dates]` 与 `db().trades`，提取唯一 name 集合，去重排序返回。保证 instruments.name 与持仓 name 口径一致（PRD §5.3 铁律 6）。
- 保存后触发 `App.DashboardController.renderSlices()` + `App.EtfOverlapController.render()` + `App.AlertBannerController.recalc()`（主数据变化可能使行业告警状态改变）。

### 5.2 PortfolioSliceService（DAA-5，纯函数）

```typescript
/** 按维度分组聚合市值占比 */
groupBy(date, dimKey): Slice[] | null
// Slice = { key, marketValue, pct, items: string[] }
// 内部：取 holdings[date]（未清仓）+ instruments + overview[date].total_assets
// total_assets 缺失 → null

/** 勾稽校验 */
verifyTotals(slices, totalAssets): {sumPct, cashPct, diff}
// sumPct = Σ slices.pct；cashPct = (totalAssets - ΣmarketValue)/totalAssets*100
// diff = |sumPct + cashPct - 100|，应 < 0.1（浮点误差）
```

- 为 AlertService 行业告警提供 `groupBy(date, 'industry')` 结果。
- 为 WhatIfService 提供 `groupBy(simulatedHoldings, instruments, simTotalAssets, 'industry')`（重载：直接传入模拟数据，不从 DB 取）。

### 5.3 EtfOverlapService（DAA-6，纯函数）

```typescript
/** 计算持仓中所有 ETF 相关两两组合的重叠度 */
detect(date): OverlapPair[]
// OverlapPair = { a, b, overlap: string[], ratio: number }
// 内部：
//   holdings = 当日未清仓持仓 name 集合
//   for each pair (a, b) where a < b and (isEtf(a) or isEtf(b)):
//     S_a = isEtf(a) ? instruments[a].etf_top10 : [a]
//     S_b = isEtf(b) ? instruments[b].etf_top10 : [b]
//     if S_a empty or S_b empty → skip（数据不足）
//     overlap = S_a ∩ S_b
//     ratio = overlap.length / min(S_a.length, S_b.length)
//   按 ratio 降序返回
```

- **科创50+科创半导铁律**：只要两者 etf_top10 有交集，ratio 必然 >0；若交集 ≥2 只（各 10 只中 min=10，交集 2 → ratio=0.2 > 0.15）即触发提醒。实际两者成分股高度重叠，必然触发。
- ETF↔个股：`S_b = [个股name]`，若该 name ∈ ETF.top10 → ratio = 1/1 = 100%。

### 5.4 WhatIfService（DAA-7，纯函数，不落库）

```typescript
/** 模拟单笔交易后的组合状态 */
simulate(date, trade): WhatIfResult | null
// trade = {name, action:'buy'|'add'|'sell'|'reduce', amount, price}
// 内部：
//   1. holdings = deepClone(db().holdings[date])
//   2. overview = deepClone(db().overview[date])
//   3. applyTrade(holdings, overview, trade)  // 修改副本
//   4. water = AlertService.calcWaterLevel(simOverview, plan)
//   5. alerts = AlertService.evaluateAlertsWith(simOverview, simHoldings, plan)
//      （evaluateAlertsWith 为新增重载，接受传入的 overview/holdings 而非按 date 取 DB）
//   6. slices = PortfolioSliceService.groupByWith(simHoldings, instruments, simOverview.total_assets, 'industry')
//   7. 返回 {water, alerts, slices, simOverview, simHoldings}
// total_assets 缺失或 trade 非法 → null

/** 校验交易合法性 */
validateTrade(date, trade): {valid, errors}
// sell/reduce 时 amount ≤ 当前持仓 position；否则报错
```

**不落库铁律实现**：`simulate` 全程操作深拷贝对象，不调用任何 `db().xxx =` 或 `saveXxx()`。`applyTrade` 为纯函数，输入输出均为副本。

**applyTrade 逻辑**：

```javascript
function applyTrade(holdings, overview, trade) {
  const idx = holdings.findIndex(h => h.name === trade.name);
  if (trade.action === 'buy' || trade.action === 'add') {
    if (idx >= 0) {
      // 加仓：加权平均成本
      const h = holdings[idx];
      const totalCost = h.cost * h.position + trade.price * trade.amount;
      h.position += trade.amount;
      h.cost = totalCost / h.position;
      h.current_price = trade.price;
    } else {
      // 新买入
      holdings.push({
        name: trade.name, position: trade.amount, available: trade.amount,
        cost: trade.price, current_price: trade.price,
        market_value: trade.amount * trade.price, cleared: false
      });
    }
  } else { // sell/reduce
    if (idx < 0) return {error: '持仓不存在'};
    const h = holdings[idx];
    h.position -= trade.amount;
    if (h.position <= 0) { h.position = 0; h.cleared = true; h.market_value = 0; }
    else { h.market_value = h.position * h.current_price; }
  }
  // 重算总市值（现金自动反向变化，总资产不变）
  overview.market_value = holdings.reduce((s,h) => s + (h.market_value||0), 0);
  return {ok: true};
}
```

### 5.5 AlertService 扩展（DAA-3 industry 维度）

在 `DIM_EVALUATORS` 中追加：

```javascript
industry: function(ctx) {
  const slices = App.PortfolioSliceService.groupBy(ctx.date, 'industry');
  if (!slices) return [];
  const max = ctx.plan.single_industry_max;
  return slices
    .filter(s => s.pct > max)
    .map(s => ({
      dim: 'industry', name: s.key, threshold: max, actual: s.pct,
      dev_pp: round1(s.pct - max),
      message: `${s.key} 占比 ${s.pct.toFixed(1)}%，超过单行业上限 ${max}%`,
      target: { type: 'slice', anchor: 'industry', value: s.key }
    }));
}
```

- `evaluateAlerts` 内部已遍历 `Object.keys(DIM_EVALUATORS)`，新增 industry 自动纳入，无需改主流程。
- 行业告警的忽略键 = `industry:行业名`，复用 v1.2 `filterIgnored` 机制。

### 5.6 DashboardController 扩展（切片 Tab + 主数据入口）

## 八、关键技术点与难点

### 8.1 难点 1：instruments.name 与 holdings.name 的一致性

- **问题**：instruments 以 name 为主键，若用户手动输入与持仓 name 不一致（多空格、大小写、简称 vs 全称），切片时该标的归入"未分类"。
- **方案**：`InstrumentController.openEditor` 的标的选择用 `<select>`，options 来源于 `InstrumentService.getAllHoldingNames()`，禁止自由输入新 name（PRD §5.3 铁律 6）。新增标的必须先在持仓中出现（通过交易录入或快照录入），再补主数据。
- **兜底**：切片时若 name 未匹配 instruments，归入"未分类"并在 UI 标注数量，引导补录。

### 8.2 难点 2：What-If 深拷贝与纯函数边界

- **问题**：模拟交易必须不污染真实数据；同时需复用 AlertService/PortfolioSliceService 的纯计算逻辑。
- **方案**：
  1. `WhatIfService.simulate` 首步 `JSON.parse(JSON.stringify(holdings))` 深拷贝（持仓对象无函数，JSON 深拷贝安全）。
  2. 为 AlertService/PortfolioSliceService 增加 `*With` 重载，接受传入的 overview/holdings 参数而非从 DB 取。
  3. `WhatIfController` 只调用 `simulate`，不持有 DB 引用。
- **测试保障**：单元测试断言 simulate 前后 `db().holdings[date]` 与 `db().overview[date]` 完全不变（深拷贝校验）。

### 8.3 难点 3：切片占比勾稽校验

- **问题**：行业占比合计 + 现金应 = 100%，浮点误差可能导致 UI 显示不一致。
- **方案**：`PortfolioSliceService.verifyTotals` 返回 `diff = |sumPct + cashPct - 100|`，UI 显示勾稽值 `ΣXX.X% + 现金 XX.X% = 100.X%`，若 `diff > 0.5` 则红色提示"数据异常"（正常浮点误差 < 0.1）。
- 浮点误差来源：各 pct 保留 1 位小数后求和。显示用原始 pct 求和后统一 round，避免逐行 round 累积误差。

### 8.4 难点 4：ETF 成分股口径差异

- **问题**：etf_top10 中的成分股名称（如"中芯国际"）需与持仓中标的 name 完全一致才能被交集检测识别。
- **方案**：
  1. 不做模糊匹配（PRD §1.4 永久不做智能识别）。
  2. `InstrumentController` 编辑 etf_top10 时提供"从持仓名称中选择"的下拉辅助（基于 `getAllHoldingNames`），减少手动输入不一致。
  3. 重叠面板底部提示"若成分股名称与持仓名称不一致，可能漏报"。

### 8.5 难点 5：Chart.js 多维度切换的实例管理

- **问题**：v1.2 已有 pieChart（标的）实例，v1.3 切换行业/风格时需复用同一实例改数据，避免销毁重建。
- **方案**：`DashboardController` 维护 `currentSliceDim` 变量，`renderSlices()` 根据维度构造不同的 `chart.data` 后调用 `chart.update()`。配色：industry 用 Chart.js 默认调色板；style 用 `STYLE_COLOR` 固定映射。
- 条形图（barChart）同理。

### 17.1 版本号与交付目录

| 项 | 本文档 | 实际实现 | 说明 |

### 17.2 cleared 字段类型（与伪代码不一致）

- **本文档伪代码**（5.4 节 applyTrade）：`h.cleared = true`
- **实际实现**：`h.cleared = 1`（沿用 v1.2.3 数据模型 `0/1` 整数标识）
- **原因**：v1.2.3 `models.createHoldingRow` 中 `cleared` 初始化为 `0`，`holdingsService` 过滤条件为 `!h.cleared`（0 为假、1 为真）。What-If 深拷贝后若写入 `true`，过滤仍可工作，但为与存量数据保持类型一致，统一用 `0/1`。
- **影响**：无功能影响，仅类型一致性。

### 17.3 AlertService evaluateAlertsWith 重载

- **本文档 8.2 节**提到"为 AlertService/PortfolioSliceService 增加 `*With` 重载"。
- **实际实现**：
  - `AlertService.evaluateAlertsWith(overview, holdings, plan, suggestedCenter)` —— 新增，供 What-If 调用。
  - `PortfolioSliceService.groupByWith(holdings, instruments, totalAssets, dimKey)` —— 本文档 4.4 节已定义，实际实现一致。
- **补充**：`evaluateAlerts`（原方法）的 ctx 中新增 `instruments` 字段，industry 评估器从 ctx.instruments 取主数据，避免重复读 DB。

### 17.4 Chart.js 实例管理（实现简化）

- **本文档 8.5 节**："复用同一实例改数据，避免销毁重建"。
- **实际实现**：`DashboardController.renderSlices()` 中仍采用 `if (pieChartInst) pieChartInst.destroy(); pieChartInst = new Chart(...)` 的销毁重建方式（与 v1.2.3 原有 `renderCharts` 保持一致）。
- **原因**：v1.2.3 原实现即销毁重建，≤15 持仓场景下性能无感知差异；且行业/风格维度的 chart 配置（tooltips callback、scales max）与标的维度不同，复用实例需额外处理配置差异，复杂度高于重建。
- **影响**：性能略劣于复用方案，但远低于 11 章目标阈值（renderAll 不劣于 v1.2.3）。后续若持仓量增大可改为实例复用。

### 17.5 T13 既有测试修改

- **原因**：industry 评估器启用后，T13 三维度告警测试中的持仓标的无 instruments 记录，全部归入"未分类"，导致"未分类"占比超 single_industry_max=40% 触发额外行业告警，使原断言（alerts.length===0）失败。
- **修改**：在 T13 开始前向 DB.instruments 写入三个标的的主数据（不同行业，各自占比不超 40%），使行业维度不触发告警，保持原测试意图。
- **影响**：仅测试数据预置，不影响生产逻辑。

### 17.6 行业告警跳转机制

- **实际实现**：`AlertBannerController.gotoTarget` 增加 `target.type === 'slice'` 分支，点击"查看"时自动切换到行业 Tab 并滚动至图表区。

### 17.9 水位口径统一修复（复盘界面遗漏建议中枢参数）
