# 持仓复盘工具 产品需求文档（PRD v1.1.2 精简计算版）

> **文档定位**：本文件是 v1.1.1 的补丁版本 PRD，针对「录入端冗余字段过多」「观看界面数据噪音干扰复盘专注度」两个核心痛点做最小化修正，为后续 v1.2 大版本的技术方案奠定"只输入最小必要集，其余全部推导"的原则。
> **版本**：v1.1.2 ｜ 日期：2026-10-02 ｜ 上游依赖：PRD v1.1、v1.1.1 已交付功能
> **范围声明**：本文件**只修改现有界面和数据流，不新增功能、不引入新 Tab、不改动闭环/对账/复盘核心逻辑**。所有改动必须保证 v1.1.1 已有的数据迁移、删除/重置功能不回归。

| 项 | 内容 |
|---|---|
| v1.1.2 一句话目标 | 让录入只留最小必要输入项，让看板只展示决策相关核心指标，去除一切"券商截图里有但我根本不需要关心"的噪音 |
| 唯一用户 | 我本人（盘后 10–20 分钟复盘，持仓 5–15 只） |
| 不在 v1.1.2 范围 | 任何新增功能、任何数据模型新增字段、任何对账/复盘/交易逻辑改动 |
| 数据存储 | 保持 v1.1 结构不变，仅把部分"原输入字段"降级为"纯计算展示字段" |
| 演进兼容 | 旧数据中已有的冗余字段保留可读（向下兼容），新录入不再要求填写 |

## 二、核心用户故事

### US-P1：快速录入当日持仓，只做最少输入
**作为**我自己，**当**盘后录入当日持仓时，**我希望**只需要填标的名称、持仓量、成本、现价这四个数，
**以便**浮动盈亏、市值等衍生指标全部由系统自动算出来，减少录入负担和出错概率。

**验收路径**：手动录入弹窗 → 只填 4 列 → 保存 → 看板浮动盈亏/市值/仓位% 全部正确显示

### US-P2：看板只看决策相关指标
**作为**我自己，**当**查看持仓看板时，**我希望**不再看到"可用资金、可取资金、当日盈亏"这些对复盘决策无意义的数据，
**以便**我把注意力集中在"总资产、总市值、浮动盈亏、仓位占比"这四个真正影响明天操作决策的指标上。

**验收路径**：看板 Tab → 账户总览只显示 4 个核心指标 → 持仓卡片只显示持仓量/成本/现价/浮动盈亏

### US-P3：加仓价格与券商界面精度一致
**作为**我自己，**当**录入买入/加仓交易时，**我希望**价格输入框支持 3 位小数（与券商 App 显示的 ETF/基金价格精度一致），
**以便**不需要在脑中做四舍五入转换，减少录入误差。

**验收路径**：记一笔交易 → 选择 buy/add → 价格输入框 step=0.001 → 保存后显示 3 位小数

## 三、功能详细需求

### 3.1 P1 标的录入字段精简（手动录入弹窗）

#### 3.1.1 变更描述
手动录入弹窗（`#manualModal`）中，标的明细表格从 6 列缩减为 4 列输入列，去掉的列改为**只读计算展示**。

#### 3.1.2 表格列定义

| 列 | 类型 | 是否可输入 | 计算规则 | 备注 |
|---|---|---|---|---|
| 标的名称 | string | 是 | — | 保留 |
| 持仓量 | number | 是 | — | 保留 |
| 成本 | number | 是 | — | 保留 |
| 现价 | number | 是 | — | 保留 |
| ~~可用持仓~~ | ~~number~~ | ~~否（删除输入）~~ | ~~= 持仓量~~ | **去除输入列** |
| ~~浮动盈亏~~ | ~~number~~ | ~~否（删除输入）~~ | ~~= 持仓量 × (现价 − 成本)~~ | **改为计算展示** |

#### 3.1.3 交互变更

```
[变更前] 表格 6 列输入：名称 | 持仓量 | 可用 | 成本 | 现价 | 浮动盈亏
[变更后] 表格 4 列输入 + 1 列计算展示：名称 | 持仓量 | 成本 | 现价 | 浮动盈亏（只读）
```

- **输入行**：用户只填写名称、持仓量、成本、现价；
- **实时计算列**：在表格右侧新增一列只读单元格，当「持仓量、成本、现价」三值均非空时，实时计算并显示：
  - `浮动盈亏 = 持仓量 × (现价 − 成本)`，保留 2 位小数；
  - 同时显示盈亏比例：`浮动盈亏比例 = (现价 − 成本) / 成本 × 100%`；
  - 颜色跟随盈亏状态（红涨绿跌，A 股色编码）。
- **保存逻辑**：`collectHoldings()` 中继续按原公式计算 `market_value`、`floating_pnl`、`floating_pnl_pct`，只是 `available` 字段自动填充为 `position`（单用户场景下可用=持仓始终成立）。

#### 3.1.4 校验规则

- 保留现有校验：标的名称非空、持仓量为正整数、现价为正数；
- **新增软提示**：若成本 > 现价（浮亏），在只读盈亏列旁边显示灰色小字「浮亏」；若成本 < 现价，显示「浮盈」。

### 3.2 P2 账户总览卡片精简（看板 + 录入弹窗 overview 区）

#### 3.2.1 看板展示层变更

**[变更前]** 看板账户总览区域：
```
┌─────────┬─────────┬──────────┬────────────┐
│ 总资产   │ 总市值   │ 浮动盈亏  │ 当日参考盈亏 │  ← 4 大卡片
├─────────┴─────────┴──────────┴────────────┤
│ 可用资金        │ 可取资金       │ 仓位%      │  ← 3 小卡片
└───────────────────────────────────────────┘
```

**[变更后]** 看板账户总览区域：
```
┌─────────┬─────────┬──────────┬────────┐
│ 总资产   │ 总市值   │ 浮动盈亏  │ 仓位%   │  ← 4 大卡片，全部一行
└─────────┴─────────┴──────────┴────────┘
```

| 卡片 | 数据来源 | 展示规则 |
|---|---|---|
| **总资产** | 手动输入（overview.total_assets） | 黑色大字，始终显示；若未录入显示「—」 |
| **总市值** | **计算** = Σ(各标的持仓量 × 现价) | 黑色大字；仅当总资产有值时，卡片下方小字显示「仓位 = 总市值/总资产」 |
| **浮动盈亏** | **计算** = Σ(各标的浮动盈亏) | 红绿色大字（红涨绿跌），始终显示 |
| **仓位%** | **计算** = 总市值 / 总资产 × 100% | 黑色大字；若总资产为空则显示「—」 |

- **去除**：可用资金卡片、可取资金卡片、当日参考盈亏卡片、当日盈亏比例小字；
- **新增**：仓位% 从下方小卡片上移为大卡片，与总市值/浮动盈亏并列；
- **保留**：总市值卡片下方的仓位小字（作为冗余提示，v1.2 可决定是否保留）。

#### 3.2.2 录入弹窗 overview 区变更

手动录入弹窗的 overview 输入区（`#mn-overviewGrid`）从 8 字段缩减为 **1 字段**：

| 字段 | 变更 |
|---|---|
| **总资产** | **保留输入**（唯一需要手填的总览字段） |
| ~~总市值~~ | ~~删除输入框，改为计算展示~~ |
| ~~浮动盈亏~~ | ~~删除输入框，改为计算展示~~ |
| ~~当日盈亏~~ | ~~删除输入框，不展示~~ |
| ~~当日盈亏%~~ | ~~删除输入框，不展示~~ |
| ~~可用资金~~ | ~~删除输入框，不展示~~ |
| ~~可取资金~~ | ~~删除输入框，不展示~~ |
| ~~仓位%~~ | ~~删除输入框，改为计算展示~~ |

**[变更后 overview 区布局]**：
```
┌─────────────────────────────────────────────┐
│  总资产  [________输入框________]            │
├─────────────────────────────────────────────┤
│  总市值：¥12,345.67   浮动盈亏：+¥1,234.56   │
│  仓位：68.5%                                 │
└─────────────────────────────────────────────┘
         ↑ 三行灰色小字，根据下方持仓表实时计算
```

- 用户在 overview 区只输入总资产；
- 当用户填写下方持仓明细表时，overview 区实时计算并显示总市值、浮动盈亏、仓位%；
- 若用户尚未填写任何持仓行，计算区显示「—」。

#### 3.2.3 计算规则汇总

```javascript
// 单条标的
market_value_i     = position_i × current_price_i
floating_pnl_i     = position_i × (current_price_i − cost_i)
floating_pnl_pct_i = (current_price_i − cost_i) / cost_i × 100%

// 总览聚合
total_market_value = Σ market_value_i
total_floating_pnl = Σ floating_pnl_i
position_pct       = total_market_value / total_assets × 100%   (total_assets > 0)
```

### 3.4 P4 交易价格精度调整

#### 3.4.1 变更范围

| 输入框 | 变更前 | 变更后 | 理由 |
|---|---|---|---|
| 买入/加仓价格 (`#bf-price`) | `step="0.0001"` | `step="0.001"` | ETF/基金价格通常 3 位小数 |
| 目标区间下沿 (`#bf-targetLow`) | `step="0.0001"` | `step="0.001"` | 与买入价格精度一致 |
| 目标区间上沿 (`#bf-targetHigh`) | `step="0.0001"` | `step="0.001"` | 与买入价格精度一致 |
| 止损位 (`#bf-stopLoss`) | `step="0.0001"` | `step="0.001"` | 与买入价格精度一致 |
| 卖出/减仓/清仓价格 (`#sf-price`) | `step="0.0001"` | **保持 `0.0001`** | 卖出成交价可能更精细，保留 4 位 |

#### 3.4.2 相关联动

- `App.Models.createTrade()` 中 `price` 字段的存储精度不变（JavaScript number 本身不限制小数位）；
- 交易流水列表中价格展示保留原格式化逻辑（`U().fmt()` 会自动去除末尾无意义的 0）；
- 对账引擎中的价格比较逻辑不受精度变化影响。

### 3.6 P6 图表数据源调整

#### 3.6.1 变更描述
看板右侧「当日盈亏排行」柱状图改为「**浮动盈亏排行**」柱状图，数据源从 `day_pnl` 切换为 `floating_pnl`。

#### 3.6.2 理由
- 「当日盈亏」需要"昨日持仓数据"作为基准才能计算，在只有当日快照的情况下无法准确得出；
- 「浮动盈亏」= 持仓量 × (现价 − 成本)，仅依赖当日数据即可计算，逻辑自洽；
- 浮动盈亏更能反映当前持仓的真实盈亏状态，是复盘时更关注的指标。

#### 3.6.3 图表标题变更
- 标题从「当日盈亏排行」改为「**浮动盈亏排行**」；
- 颜色规则不变：红柱 = 正数（浮盈），绿柱 = 负数（浮亏）；
- 无数据时显示「暂无持仓数据」占位文案。

## 四、数据模型变更说明

### 4.1 字段职责重新划分

v1.1.2 不改变 `DB.overview` 和 `DB.holdings` 的数据结构（向下兼容旧数据），只重新划分「输入职责」与「计算职责」：

```javascript
// ========== DB.holdings[date][i] ==========
// 变更前：以下字段都需要用户在录入时填写或 OCR 预填
// 变更后：只有 ★ 标记的字段需要输入，其余为计算字段

{
  date,            // 自动
  name,            // ★ 用户输入
  market_value,    // 计算 = position × current_price
  position,        // ★ 用户输入
  available,       // 计算 = position（单用户场景）
  cost,            // ★ 用户输入
  current_price,   // ★ 用户输入
  day_pnl,         // 不展示、不计算（v1.1.2 废弃）
  day_pnl_pct,     // 不展示、不计算（v1.1.2 废弃）
  floating_pnl,    // 计算 = position × (current_price − cost)
  floating_pnl_pct,// 计算 = (current_price − cost) / cost × 100%
  cleared          // 计算（由清仓交易触发）
}

// ========== DB.overview[date] ==========
// 变更后：只有 total_assets 需要输入，其余为计算字段

{
  date,            // 自动
  total_assets,    // ★ 用户输入（现金+市值的总和，无法从持仓推导）
  market_value,    // 计算 = Σ holdings.market_value
  floating_pnl,    // 计算 = Σ holdings.floating_pnl
  day_pnl,         // 不展示、不计算（v1.1.2 废弃）
  day_pnl_pct,     // 不展示、不计算（v1.1.2 废弃）
  available,       // 不展示（v1.1.2 废弃）
  withdrawable,    // 不展示（v1.1.2 废弃）
  position_pct     // 计算 = market_value / total_assets × 100%
}
```

### 4.2 旧数据兼容策略

- **读取**：旧数据中已有的 `available`、`withdrawable`、`day_pnl`、`day_pnl_pct` 等字段继续可读，看板不再展示；
- **写入**：新保存的数据中，`available` 自动设为 `position`，`day_pnl`/`day_pnl_pct` 设为 `null`；
- **OCR 旧截图**：已确认的旧快照数据不受影响，继续正常展示；若重新编辑，按新精简规则呈现。

### 5.3 关键交互铁律

1. **计算字段不可编辑**：所有标记为「计算」的字段，在录入弹窗中以 `<span>` 或 `disabled input` 展示，用户无法直接修改；
2. **实时计算**：在手动录入弹窗中，修改持仓量/成本/现价的任意一个输入框后，100ms 内更新同行的浮动盈亏列和 overview 区的聚合值（使用防抖）；
3. **保存时自动补全**：`collectHoldings()` 和 `collectOverview()` 在保存前自动执行完整计算，确保落库数据与展示一致；
4. **向下兼容**：旧数据打开后正常展示，不因为缺少新字段而报错。

## 六、异常处理与边界条件

| 场景 | 处理 |
|---|---|
| 成本 = 0 或 null | 浮动盈亏显示「—」，不计算比例（避免除零） |
| 现价 = 0 或 null | 市值显示「—」，浮动盈亏显示「—」 |
| 持仓量 = 0 | 视为已清仓或空行，市值/盈亏均显示「—」 |
| 总资产 = 0 或 null | 仓位% 显示「—」 |
| 总持仓为空 | 总市值显示「—」，浮动盈亏显示「—」，仓位% 显示「—」 |
| 旧数据中的 `day_pnl` 有值 | 正常读取但不展示，保存时覆写为 `null` |
| OCR 识别出 `available` | 忽略该字段，只使用 `position`/`cost`/`current_price` |
| 加仓价格输入 4 位小数 | 输入框 `step="0.001"` 限制为 3 位，超出位数四舍五入 |
