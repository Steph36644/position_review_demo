# 持仓复盘工具 PRD（V2.0 私人复盘版）

> 文档定位：基于《持仓复盘工具 需求分析报告 V2.0》（重构版）输出，**目标用户从"市场个人投资者"收窄为"用户本人"**，功能架构以三大核心痛点为出发点重新规划，研发可直接据此明确开发范围。
> 版本：V2.0  日期：2026-09-29  来源：需求分析报告 V2.0
> 替代：原 PRD V2.0（面向市场版）——原 PRD 中"目标用户分层 / 商业化定位 / 付费意愿"等内容已失效，本版本完全替代。

## 一、产品概述

### 1.1 产品核心价值

**一个私人持仓复盘工具，服务于我自己，目标是把"交易体系"变成"可被追踪、可被校验、可被追责"的执行闭环。**

工具不为任何人else而做，只为我自己用。设计标准只有一条：**"我是否真的会每天用"**。

### 1.2 产品的最终目标（判定标准）

工具的存在价值由 **三条可验证的目标** 判定（来自需求分析报告 1.3 节）：

1. **买卖理由闭环**：每一笔买入和卖出，其背后的理由必须对应且充分——卖出时的理由应当能直接追溯到买入时的理由（证伪 / 兑现 / 失效），不允许出现"忘了为什么买、糊里糊涂就卖了"的交易。
2. **盈亏归因到体系**：赚的是"交易体系该赚的钱"，亏的是"交易体系内的正常风控成本"。凡是不符合体系的盈亏，都要被识别为"违规操作"并单独标记。
3. **整体仓位抗系统性风险**：在大盘系统性下跌时，组合回撤必须落在预设的可接受区间内——这是仓位整体性的最终检验。

### 1.3 解决的核心痛点（重构后）

原 PRD 列举的 6 个痛点已被重新归纳为 **3 个核心痛点**，每个痛点对应一组功能模块：

| 痛点 | 根因 | 对应解决模块 | 关键功能 |
|---|---|---|---|
| **痛点1：买入理由 ≠ 卖出理由，没有贯彻"同一理由"** | 买入理由没有结构化沉淀，卖出动作没有强制对照 | **理由闭环追踪模块** | 买入理由结构化记录 / 卖出理由强制对照 / 兑现-证伪-失效-违规四分类 / 违规交易清单 |
| **痛点2：仓位管理没有整体性，每笔交易缺乏对整体仓位的考量** | 交易动作在标的粒度，风险发生在组合粒度 | **整体仓位管理模块** | 仓位计划（目标带/上限/下限）/ What-If 预演 / 仓位水位仪表 / 集中度告警 |
| **痛点3：仓位分散度缺乏理解** | 缺乏对持仓"风险结构"的透视 | **分散度透视模块** | 行业切片 / 风格切片 / 市场切片 / ETF 重叠检测 / 等效独立持仓数 |
| 横向支撑 | — | **日常复盘闭环模块** | 每日复盘模板 / 盈亏归因到"体系内 vs 体系外" / 系统性风险对照 |

### 1.4 产品整体定位

**私人持仓复盘工具，唯一用户是我本人。**

- 不做市场推广，不考虑拉新、留存、转化等产品指标
- 不做社交、不做分享、不做 AI 荐股
- 所有功能的设计标准是"我是否真的会每天用"

### 1.5 本次版本明确不做的功能边界（V2.0 全系列排除清单）

> 以下功能 **不在 V2.0 全系列范围内**，研发团队无须实现，避免工具变形。

**A. 后续版本规划项（V3.0 / V4.0）**
- 系统性风险对照（P1-5）→ V3.0（周复盘用）
- 仓位变化时间线（P1-6）→ V3.0
- 历史复盘检索（S3）→ V3.0
- 每周回顾视图（S4）→ V3.0
- 违规交易统计（R4）→ V3.0
- 集中度指标 HHI（D6）→ V3.0
- 市场切片（D3）→ V3.0（当前持仓以 A 股为主，需求弱）
- 理由命中率（R5）→ V4.0（需 3+ 月数据积累）
- 等效独立持仓数（D5）→ V4.0（相关性数据获取成本高，先用手工打标）

**B. 永久不做项（与定位冲突，明确排除）**
- ✗ 实时行情（券商 App 的职责，每日手动录入收盘价即可）
- ✗ AI 荐股 / 买卖建议（违背"体系内化"目标）
- ✗ 社区 / 分享 / 抄作业（个人工具）
- ✗ 多用户 / 账户体系（只有自己用）
- ✗ 复杂回测 / 蒙特卡洛 / 因子分析（超出当前痛点范围）
- ✗ 税务 / 分红 / 多币种（当前用不到）
- ✗ 一键下单（与"复盘工具"定位冲突）

## 二、目标用户

### 2.1 唯一目标用户：我本人

| 维度 | 特征 |
|---|---|
| 身份 | 散户，体量不足以量化 |
| 资金规模 | 有限 |
| 持仓数量 | 5–15 只标的 |
| 复盘时间 | 每日收盘后 10–20 分钟 |
| 投资风格 | 中长线为主，部分短线 |
| 市场覆盖 | 以 A 股为主，含 ETF 与部分港美股 |

### 2.2 核心诉求

按三大痛点对应的需求层级展开：

1. **理由闭环诉求**（对应痛点1）
   - 每笔买入必须有结构化理由字段
   - 每次卖出必须显式选择与买入理由的关系（兑现/证伪/失效/违规）
   - 历史上每只标的的"买-卖"配对可追溯
   - 违规交易单独标记，可统计

2. **整体仓位诉求**（对应痛点2）
   - 设定整体仓位计划（目标带、单标的上限、行业上限、现金下限）
   - 任何交易前可预演对整体仓位的影响
   - 仓位水位仪表回答"我当前是否处于自己设定的合理区间"
   - 任一维度超阈立即告警

3. **分散度诉求**（对应痛点3）
   - 多维度切片（行业 / 风格 / 市场）让"看似分散、实则集中"暴露
   - ETF 与个股之间的重叠提醒（如持有"科创50"+"科创半导"高度重叠）
   - 风险结构可透视，不是"数量多 = 分散"

4. **复盘闭环诉求**（横向支撑）
   - 每日按结构化模板复盘，不是流水账
   - 盈亏归因到"体系内 vs 体系外"
   - 大盘系统性下跌时，组合回撤可对照

### 2.3 典型使用场景

| 场景 | 频率 | 时长 | V2.0 支持情况 |
|---|---|---|---|
| **盘后日复盘** | 每交易日 | 10–20 分钟 | V2.0 全系列完整支持 |
| **调仓前预演** | 不定期 | 2–5 分钟 | V2.2 起完整支持（What-If） |
| **周末周复盘** | 每周末 | 20–30 分钟 | V3.0 起完整支持 |
| **月底/年底总结** | 不定期 | 30+ 分钟 | V3.0 起支持（含历史检索） |

### 3.2 V2.0 全系列必做功能清单（按子版本分组）

V2.0 拆分为 **3 个子版本**（V2.0 / V2.1 / V2.2），每个子版本都是可独立交付的闭环。

#### V2.0（理由闭环版）—— 第一迭代

| ID | 功能名称 | 优先级 | 功能简要说明 | 验收要点 |
|---|---|---|---|---|
| **R1** | 买入理由结构化记录 | P0 | 新建/加仓时必须填写结构化字段 | 字段：标的 / 核心理由（一句话）/ 理由类型（基本面/技术面/事件/估值/情绪）/ 预期持有周期 / 失效条件 / 目标区间 / 止损位；**必填校验**，不填不允许保存 |
| **R2** | 卖出动作强制对照 | P0 | 卖出/减仓时必须选择卖出类型 | 四选一：①理由兑现 ②理由证伪 ③理由失效 ④违规卖出（无对应理由）；并填写一句话说明；**必填校验**，不选不允许保存 |

| ID | 功能名称 | 优先级 | 功能简要说明 | 验收要点 |

## 四、界面设计要求

### 4.1 整体交互风格

沿用 V1.0 现有设计语言，保持视觉与交互一致性：

- **设计语言**：轻量级玻璃拟态（glass-morphism）+ 卡片化布局
- **色彩系统**：
  - 主色：中性 slate-50 / slate-800
  - 涨跌色：A 股色编码 红涨绿跌（涨 #dc2626 / 跌 #16a34a）
  - 状态色：仓位水位 超出目标带红 / 在带内绿 / 低于下限黄；风控超阈红；违规交易红
  - 理由闭环色：兑现绿 / 证伪红 / 失效灰 / 违规深红
- **字体**：Inter + Noto Sans SC，数字使用 `tabular-nums` 对齐
- **信息密度**：每个新增模块必须有数据支撑（不堆砌空 UI）
- **响应式断点**：V2.0 先做 PC 端（移动端响应式不在范围内）

### 4.2 核心页面设计原则

V2.0 在 V1.0 单页布局基础上扩展为以下核心区域（按子版本渐进扩展）：

**V2.0 基础布局**（在 V1.0 上扩展）：
1. **顶部告警横幅**（V2.1 起 P1-3）：默认折叠，触阈时自动展开为红色横幅，**不打断用户当前操作**
2. **账户总览区**：保留 V1.0 7 个汇总字段，**V2.1 新增仓位水位仪表（P1-2）**作为第 8 个核心指标
3. **持仓明细卡片**：**改造 V1.0 的"交易计划/备注"自由文本框** → 拆分为 R1 结构化字段（买入理由 / 理由类型 / 预期周期 / 失效条件 / 目标区间 / 止损位）
4. **结构化复盘区**（S1）：替代 V1.0 自由文本，**4 段式折叠面板**
5. **理由-交易对账页**（R3）：**新增独立 Tab/页面**，按标的分组展示买卖配对
6. **交易流水区**（R1/R2）：**新增独立 Tab/页面**，每次加仓/减仓/清仓记一笔，强制选择卖出类型

**V2.2 扩展布局**：
7. **多维度切片区**（D1/D2）：改造 V1.0 单环形图 → 维度切换 Tab（标的/行业/风格）
8. **重叠检测面板**（D4）：新增，列出 ETF 与个股的重叠矩阵
9. **What-If 预演抽屉**（P1-4）：新增侧边抽屉，输入拟交易实时预演

### 4.3 关键交互流程规范

1. **买入理由录入流程**（R1）：
   - 新建持仓或加仓 → 弹出理由录入弹窗
   - 填写 7 个字段（标的自动带入，其余手动填）
   - **必填校验**：核心理由 / 理由类型 / 失效条件 / 目标区间 / 止损位，缺一不可
   - 保存 → 写入 DB.trades 流水表

2. **卖出强制对照流程**（R2）：
   - 卖出/减仓动作触发 → 弹出对照弹窗
   - **自动展示该标的所有未平仓买入记录及其理由**
   - 用户选择：①兑现 ②证伪 ③失效 ④违规
   - 若选"兑现/证伪/失效" → 必须关联到具体买入记录（linked_buy_id）
   - 若选"违规" → 强制填写一句话说明
   - **必填校验**，不选不允许保存

3. **理由对账查看流程**（R3）：
   - 进入"理由对账"Tab → 按标的分组展示买卖配对
   - 每对配对显示：买入日期 / 买入理由 / 卖出日期 / 卖出类型 / 是否闭环
   - **违规交易红色高亮**，独立成"违规清单"小节

4. **仓位水位查看流程**（P1-2）：
   - 总览区水位仪表 → 环形进度条显示当前仓位在目标带中的位置
   - 仪表含 3 段色带：低于下限黄 / 在带内绿 / 超出上限红
   - 点击仪表 → 展开详情：偏离目标带的差值 + 各维度告警状态

5. **集中度告警流程**（P1-3）：
   - 任一维度超阈 → 顶部横幅自动展开
   - 横幅含"查看详情"按钮 → 点击跳转到对应切片视图
   - 横幅含"今日忽略"按钮 → 标记为已确认，不再弹出（但记录到复盘模板）

6. **What-If 预演流程**（P1-4）：
   - 点击右上角"What-If"按钮 → 侧边抽屉滑出
   - 输入：标的 / 拟买/卖 / 金额 / 价格
   - 实时计算并展示：交易后总仓位 / 单标的占比 / 行业占比 / 是否触发告警
   - 与当前状态对比展示（前/后对比）
   - **仅预演，不执行**（无下单能力）

7. **盈亏归因流程**（S2）：
   - 复盘区"盈亏归因"段 → 自动列出当日所有持仓盈亏
   - 每只持仓旁有归因下拉：符合体系预期 / 超出体系预期 / 体系外噪声
   - **默认值规则**：理由未变 → 体系内；违规交易 → 强制体系外；用户可手动调整

8. **结构化复盘填充流程**（S1）：
   - 进入复盘区 → 4 段折叠面板
   - "一键填入今日快照"按钮 → 自动填入：今日操作清单（从 R1/R2 流水聚合）/ 盈亏归因初值（从 S2 规则）/ 仓位水位状态（从 P1-2）
   - 用户在此基础上补充主观判断和明日计划

## 五、版本迭代计划

### 5.1 V2.0 全系列迭代路线图

V2.0 拆分为 **3 个可独立交付的子版本**，每个子版本都形成可用闭环：

```
V2.0 理由闭环版          V2.1 仓位整体性版        V2.2 What-If+分散度版
   │                         │                         │
   ├─ R1 买入理由            ├─ P1-1 仓位计划          ├─ P1-4 What-If 预演
   ├─ R2 卖出对照            ├─ P1-2 水位仪表          ├─ D1 行业切片
   ├─ R3 对账视图            ├─ P1-3 集中度告警        ├─ D2 风格切片
   └─ S1 复盘模板(基础)      └─ S2 盈亏归因到体系      └─ D4 ETF 重叠检测
        │                         │                         │
        ▼                         ▼                         ▼
   理由闭环可追溯            仓位整体性可监控         交易前可预演+分散度可透视
```

#### V2.0 理由闭环版（第一迭代）

| 维度 | 内容 |
|---|---|

| **功能范围** | R1 + R2 + R3 + S1（共 4 项 P0） |
| **优先级** | 最高（需求分析报告第五节排名 1/2/3/6） |
| **交付标准** | 1. 任何买入/加仓必须填齐 R1 字段才能保存<br>2. 任何卖出/减仓必须选 R2 类型才能保存<br>3. 理由对账页可按标的查看买卖配对<br>4. 复盘模板 4 段式可用，可一键填入今日操作快照 |
| **前置依赖** | 无 |
| **数据模型变更** | 新增 DB.trades 流水表 + DB.reviews 结构化复盘表（见第六节） |
| **成功判定** | 所有未平仓持仓都有完整的买入理由字段（目标 100%） |

| **交付标准** | 1. 可设定 4 项仓位计划参数（目标带/单标的上限/行业上限/现金下限）<br>2. 仓位水位仪表可视化当前仓位在目标带中的位置<br>3. 任一维度超阈顶部红色横幅告警<br>4. 盈亏归因可分类为体系内/体系外，与 R1/R2 联动 |

### 5.5 关键技术建议

1. **数据模型**：从 V1.0 单日 localStorage → 引入 **"标的主数据 + 交易流水 + 仓位计划 + 复盘记录"** 四表结构（详见第六节）
2. **本地优先**：保持 V1.0 的 localStorage 策略，**不做云同步**（与定位冲突）
3. **行业映射**：直接复用 **申万一级（A 股）、恒生（港股）**，不自建
4. **理由闭环校验**：R1/R2 的必填校验在保存按钮层强制执行，不允许跳过
5. **盈亏归因联动规则**：S2 的默认值规则要写在代码层，用户可覆盖但要有日志

### 5.6 风险提示

| 风险 | 影响 | 缓解 |
|---|---|---|
| 买入理由回填成本高 | 用户放弃使用 | V2.0 上线后第一周专注回填，不强制其他功能 |
| 仓位水位算法主观 | 信任度下降 | V2.1 采用"目标带 + 偏离值"显式呈现，不引入黑盒加权分 |
| ETF 成分股数据获取 | D4 重叠检测受阻 | 优先用免费接口（东方财富/新浪），关键数据手动补录 |
| 功能扩张过快 | 流失主力用户（即我自己） | 严格按 3 个子版本迭代，每个子版本独立闭环 |

## 七、成功判定（V2.0 全系列上线 1 个月后）

工具上线 1 个月后，用以下 **5 条可验证的指标** 判断成功（来自需求分析报告第八节）：

| 指标 | 目标 | 判定来源 |
|---|---|---|
| **理由覆盖率** | 所有未平仓持仓都有完整买入理由字段（100%） | R1 字段完整性 |
| **卖出闭环率** | 本月所有卖出动作都有 sell_type 且非"违规"（≥ 90%） | R2 字段 + sell_type |
| **违规交易次数** | 本月违规卖出次数 ≤ 1 次 | R2 sell_type=违规 |
| **仓位在带率** | 本月交易日中，仓位落在目标带内的天数占比 ≥ 80% | P1-2 水位记录 |
| **系统性风险对照** | 若本月大盘跌 >5%，组合回撤 ≤ 大盘回撤 × 1.2 | V3.0 P1-5 才能完整判定 |

**注**：第 5 条完整判定需 V3.0 上线 P1-5 系统性风险对照；V2.0 阶段可手动计算。

若 5 条全部达成，说明工具真正在帮我执行交易体系；若有任意一条长期不达标，工具本身需要迭代，而不是"用得不够勤"。
