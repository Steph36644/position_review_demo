## 一、产品概述

### 1.1 一句话定位与核心价值

**一个私人持仓复盘工具，服务于我自己，目标是把"交易体系"变成"可被追踪、可被校验、可被追责"的执行闭环。**

### 1.2 v1.0 大版本核心目标（研发总纲）

**开发一款供个人用户（本人）使用的复盘工具**，在 v1.0 周期内完成以下三件事：

1. **买卖理由闭环**：每笔买入理由结构化沉淀，每次卖出强制对照买入理由（兑现 / 证伪 / 失效 / 违规四分类），消灭"忘了为什么买、糊里糊涂就卖了"。
2. **仓位整体可控**：仓位是"被设计出来的状态"而非"交易累加的结果"——有计划、有水位仪表、有超阈告警、交易前有 What-If 预演。
3. **分散度可透视**：按行业 / 风格切片 + ETF 重叠检测，让"看似分散、实则集中于同一风险因子"的持仓结构暴露出来。

### 1.3 产品最终目标（成功判定标准）

1. **买卖理由闭环**：卖出理由可直接追溯到买入理由（证伪 / 兑现 / 失效）。
2. **盈亏归因到体系**：赚的是"体系该赚的钱"，亏的是"体系内正常风控成本"；不符合体系的盈亏被识别为"违规操作"。
3. **整体仓位抗系统性风险**：大盘系统性下跌时，组合回撤落在预设可接受区间内。

### 1.4 明确不做的功能边界

**v1.x 之后再评估**：系统性风险对照、仓位时间线、历史复盘检索、每周回顾、违规统计、HHI、市场切片（v2.x）；理由命中率、等效独立持仓数（v3.x，需数据积累）。

**永久不做**：✗ 实时行情　✗ AI 荐股/买卖建议　✗ 社区/分享/抄作业　✗ 多用户账户体系　✗ 复杂回测/蒙特卡洛/因子分析　✗ 税务/分红/多币种　✗ 一键下单。

## 二、核心痛点分析（v1.0 功能设计的核心出发点，完整保留）

> 以下 3 个痛点是全部功能设计的出发点，功能模块必须能直接回答对应痛点，不做与痛点无关的功能。

### 2.1 痛点 1：买入理由 ≠ 卖出理由，没有贯彻"同一理由"

**现象**：

- 买入时基于"行业景气 + 业绩拐点"，卖出时却因为"跌得太难受"或"大盘在跌"。
- 买入理由没有被记录，卖出时无据可查。
- 事后无法判断"当初的判断是对是错"，体系无法迭代。

**根因**：买入理由没有结构化沉淀，卖出动作没有强制对照买入理由做"校验"。

**工具解法**：把"买入理由"作为持仓的第一等公民字段，**每次卖出（或减仓）必须显式选择卖出动作与买入理由的关系**——理由兑现 / 理由证伪 / 理由失效 / 无理由违规。

### 2.2 痛点 2：仓位管理没有整体性，每笔交易缺乏对整体仓位的考量

**现象**：

- 加一只票时只看它本身值不值得买，没看加上之后整体仓位、行业暴露变成多少。
- 没有"整体仓位计划"，仓位是"每笔交易累加出来的结果"，不是"被设计出来的状态"。
- 系统性风险来临时，才发现仓位早就过高，但已无退路。

**根因**：交易动作发生在标的粒度，风险发生在组合粒度；缺乏"组合视角"的决策入口。

**工具解法**：

- 给每笔拟执行交易提供 **What-If 整体仓位预览**（买入后总仓位 / 单标的占比 / 行业占比如何变化）。
- 给账户设定**整体仓位计划**（目标仓位带、单标的上限、行业上限、现金下限），任何交易先看是否破坏计划。
- 仓位水位回答："我当前是不是处于自己设定好的合理区间？"

### 2.3 痛点 3：仓位分散度缺乏理解

**现象**：

- 持仓 8 只票以为很分散，实际可能 5 只都是同一个风险因子（如都是高 β 成长股）。
- ETF 与个股之间可能存在隐形重叠（如同时持有科创50 和科创半导），实际同涨同跌。
- 分散度不是"数量多"，而是"风险来源不相关"。

**根因**：缺乏对持仓"风险结构"的透视——按行业、按风格、按相关性切片的视图。

**工具解法**：

- **多维度分散度切片**：按行业 / 风格（红利/成长/价值/周期/主题）/ 市场，让集中风险暴露。
- **重叠检测**：ETF 与个股、ETF 与 ETF 之间的重叠提醒（重叠 >15% 提醒）。
- （v3.x）**等效独立持仓数**：把高度相关持仓合并计算。

### 2.4 痛点 → 模块映射总表（功能骨架）

| 痛点   | 核心解决模块       | 关键功能                                              | 落地迭代                           |
| ---- | ------------ | ------------------------------------------------- | ------------------------------ |
| 痛点 1 | **A 理由闭环追踪** | R1 买入理由结构化 / R2 卖出强制对照 / R3 对账视图                  | **v1.1**                       |
| 痛点 2 | **B 整体仓位管理** | P1-1 仓位计划 / P1-2 水位仪表 / P1-3 集中度告警 / P1-4 What-If | P1-1\~3 **v1.2**；P1-4 **v1.3** |
| 痛点 3 | **C 分散度透视**  | D1 行业切片 / D2 风格切片 / D4 ETF 重叠检测                   | **v1.3**                       |
| 横向支撑 | **D 日常复盘闭环** | S1 结构化复盘模板 / S2 盈亏归因到体系                           | S1 **v1.1**；S2 **v1.2**        |

## 三、目标用户与使用场景（精简）

### 3.1 唯一用户：我本人

散户，体量不足以量化，资金规模有限，持仓 5–15 只；中长线为主、部分短线；以 A 股为主，含 ETF 与部分港美股；不做市场推广，不考虑拉新留存转化。

### 3.2 典型使用场景

| 场景                 | 频率   | 时长       | 支持版本       |
| ------------------ | ---- | -------- | ---------- |
| 盘后日复盘（录持仓、记流水、写复盘） | 每交易日 | 10–20 分钟 | v1.1 起完整支持 |
| 调仓前预演              | 不定期  | 2–5 分钟   | v1.3 起支持   |
| 周末周复盘              | 每周末  | 20–30 分钟 | v2.x 起完整支持 |
| 月底/年底总结            | 不定期  | 30+ 分钟   | v2.x 起支持   |

### 4.4 用户操作流程路径

**路径一：交易录入流（交易发生当天）**

```
点击"记一笔交易" → 选标的/方向/数量/价格
   ├─ 买入/加仓 → R1 弹窗填 7 字段 → 必填校验 → 写入 trades
   └─ 卖出/减仓 → R2 弹窗自动带出该标的未平仓买入记录
                   → 选 兑现/证伪/失效/违规
                   → 前三类关联 linked_buy_id；违规强制填说明
                   → 必填校验 → 写入 trades
```

**路径二：盘后复盘流（每交易日 10–20 分钟）**

```
录入当日收盘价与持仓量 → 系统生成当日 holdings 快照
   → 查看账户总览/盈亏排行（沿用现有 Demo）
   → 查看水位仪表 + 告警横幅（v1.2）/ 行业风格切片（v1.3）
   → S1 复盘模板「一键填入今日快照」（操作清单+归因初值+水位状态）
   → 补主观判断与明日计划 → 保存 reviews（localStorage 自动持久化）
   → 必要时进 R3 对账页检查买卖配对与违规标记
```

**路径三：调仓预演流（v1.3 起）**

```
点"What-If" → 抽屉输入拟买卖标的/金额/价格
   → 实时输出：交易后总仓位 / 单标的占比 / 行业占比 / 是否触阈
   → 前/后对比 → 决定是否执行（执行后走路径一，工具不下单）
```

**路径四：对账查看流（不定期）**

```
进入"理由对账"Tab → 按标的分组查看历史买-卖配对
   → 闭环状态一览 → "违规清单"小节红色高亮
```

## 五、数据获取与数据分析模块需求细化

### 5.1 设计原则

- **本地优先、手动为主**：不做实时行情（券商 App 职责），每日手动录入收盘价；所有数据存 localStorage，不做云同步。
- **接口只做辅助**：免费接口（东方财富/新浪）获取的内容必须经手动确认后才能落库，避免错误数据污染体系判定。
- **获取与分析分离**：数据获取（DAQ）负责"数据进得来、字段对得上"；数据分析（DAA）负责"指标算得准、判定有依据"。

### 5.2 数据获取模块（DAQ）

| ID        | 数据项              | 获取方式                              | 字段/内容                                                        | 版本            |
| --------- | ---------------- | --------------------------------- | ------------------------------------------------------------ | ------------- |
| **DAQ-1** | 交易流水 + 理由字段      | 手动录入（R1/R2 弹窗）                    | 方向/数量/价格 + 买入 7 字段 + 卖出类型/关联 ID/说明                           | **v1.1**      |
| **DAQ-2** | 每日收盘价与持仓量        | 手动录入（沿用现有 Demo 数据结构）              | date/name/position/available/cost/current\_price             | **v1.1**      |
| **DAQ-3** | 仓位计划参数           | 手动设置（设置面板，可随时调整）                  | 目标仓位带 / 单标的上限 / 单行业上限 / 现金下限                                 | **v1.2**      |
| **DAQ-4** | 标的主数据            | 手动维护（标的主数据编辑入口）                   | industry（申万一级/恒生）/ style（5 类）/ market / is\_etf / etf\_top10 | **v1.3**      |
| **DAQ-5** | 行业分类与 ETF 前十大成分股 | 免费接口辅助拉取 + **手动确认导入**（可选增强，非必须路径） | 预填 industry / etf\_top10，用户确认后落库 instruments                 | **v1.3**（增强项） |
| **DAQ-6** | 交易软件持仓界面截图上传 | **上传截图（PNG/JPG）** → OCR 辅助识别标的名称/持仓量/成本/现价等字段 → **手动逐项确认或修正后**方可落库 | 截图文件本身作为当日附件留存；OCR 结果仅作预填，最终以用户确认为准 | **v1.1** |

**验收要求**：
- DAQ-5 不可用或接口失败时，DAQ-4 手动路径必须能独立完成全部 v1.3 功能，不得形成硬依赖。
- DAQ-6 的 OCR 识别结果**仅作预填**，所有字段必须经用户逐项确认/修正后才能落库；识别失败时不得阻塞手动录入路径（DAQ-2）。
- 截图文件存储于本地（localStorage 以 base64 或 IndexedDB 形式），不外传，符合本地优先原则。

### 5.3 数据分析模块（DAA）

| ID        | 分析能力         | 计算逻辑                                                             | 输出形态                | 版本       |
| --------- | ------------ | ---------------------------------------------------------------- | ------------------- | -------- |
| **DAA-1** | 买卖配对与闭环判定    | 按标的将 sell/reduce/clear 经 linked\_buy\_id 与未平仓买入配对；判定 兑现/证伪/失效/违规 | R3 对账配对列表 + 违规清单    | **v1.1** |
| **DAA-2** | 仓位水位与偏离      | 当前仓位% = 总市值/总资产；与目标带比较，输出 在带内/高于上限/低于下限 + 偏离百分点                  | 水位环形仪表              | **v1.2** |
| **DAA-3** | 集中度阈值判定      | 单标的占比、单行业占比、单风格占比、现金占比分别与 plan 阈值比较                              | 正常/超阈状态 → P1-3 横幅   | **v1.2** |
| **DAA-4** | 盈亏归因联动       | 理由未变的持仓 → 默认"体系内"；sell\_type=违规 → 强制"体系外"；用户可覆盖（留痕）              | S2 归因标签 + 复盘归因段     | **v1.2** |
| **DAA-5** | 多维度切片聚合      | holdings 关联 instruments，按 industry / style 分组汇总市值占比              | 饼图 + 条形图双图 + 维度 Tab | **v1.3** |
| **DAA-6** | ETF 重叠度计算    | 取两两 ETF（及 ETF 与个股）前十大成分股交集，重叠度 = 交集市值（或数量）占比；>15% 标记提醒           | 重叠矩阵面板              | **v1.3** |
| **DAA-7** | What-If 模拟计算 | 在当前 holdings 上叠加拟交易，重算 DAA-2/DAA-3/DAA-5，输出前/后对比                 | What-If 抽屉（只读不落库）   | **v1.3** |

// 沿用现有

  id, date, name, action,            // action: buy/add/sell/reduce/clear

  expected_period, invalid_condition, target_price, stop_loss,
  sell_type, sell_note, linked_buy_id  // sell_type：兑现/证伪/失效/违规
}]

// v1.1：结构化每日复盘

// v1.1：每日持仓截图附件（DAQ-6）
DB.snapshots = { [date]: { image_base64, uploaded_at, ocr_status, confirmed:bool } }

DB.plan = { total_position_band:[60,80], single_position_max:25, single_industry_max:30, cash_min:15 }

// v1.3：标的主数据
DB.instruments = { [name]: { industry, style, market, is_etf, etf_top10:[] } }

## 九、成功判定（v1.0 全系列上线 1 个月后）

| 指标      | 目标                                                | 来源       |
| ------- | ------------------------------------------------- | -------- |
| 理由覆盖率   | 未平仓持仓买入理由字段完整率 100%                               | R1       |
| 卖出闭环率   | 当月卖出有 sell\_type 且非"违规"占比 ≥ 90%                   | R2/DAA-1 |
| 违规交易次数  | 当月违规卖出 ≤ 1 次                                      | R2       |
| 仓位在带率   | 当月仓位落在目标带内的交易日占比 ≥ 80%                            | DAA-2    |
| 系统性风险对照 | 大盘月跌 >5% 时，组合回撤 ≤ 大盘回撤 × 1.2（v1.x 期手动核算，v2.x 系统化） | 手动/P1-5  |

任一条长期不达标，迭代工具本身，而非归因于"用得不够勤"。
