# 持仓复盘工具 需求分析报告（V2.0）

> 文档定位：作为正式 PRD 的前置文档。本版本根据用户反馈重构：**目标用户从"市场个人投资者"收窄为"用户本人"**，核心痛点与产品目标全部围绕个人交易体系的纪律执行重新梳理。
> 版本：V2.0  日期：2026-09-29  替代：V1.0（面向市场版）

---

## 一、产品定位（重构后）

### 1.1 一句话定位

**一个私人持仓复盘工具，服务于我自己，目标是把"交易体系"变成"可被追踪、可被校验、可被追责"的执行闭环。**

### 1.2 目标用户

**唯一用户：我本人。** 散户，体量不足以量化，资金规模有限，持仓 5–15 只标的，每日收盘后有 10–20 分钟复盘时间。

- 不做市场推广，不考虑拉新、留存、转化等产品指标。
- 不做社交、不做分享、不做 AI 荐股。
- 所有功能的设计标准是"我是否真的会每天用"。

### 1.3 产品的最终目标（判定标准）

工具的存在价值由三条可验证的目标判定：

1. **买卖理由闭环**：每一笔买入和每一笔卖出，其背后的理由必须对应且充分——卖出时的理由应当能直接追溯到买入时的理由（证伪 / 兑现 / 失效），不允许出现"忘了为什么买、糊里糊涂就卖了"的交易。
2. **盈亏归因到体系**：赚的是"交易体系该赚的钱"，亏的是"交易体系内的正常风控成本"。凡是不符合体系的盈亏，都要被识别为"违规操作"并单独标记。
3. **整体仓位抗系统性风险**：在大盘系统性下跌时，组合回撤必须落在预设的可接受区间内——这是仓位整体性的最终检验。

## 二、核心痛点（重构后）

按用户自述重新归纳，共 3 个核心痛点，每一条都对应一组具体行为后果：

### 痛点 1：买入理由 ≠ 卖出理由，没有贯彻"同一理由"

**现象**：
- 买入时基于"行业景气 + 业绩拐点"，卖出时却因为"跌得太难受"或"大盘在跌"。
- 买入理由没有被记录，卖出时无据可查。
- 事后回顾无法判断"当初的判断是对是错"，体系无法迭代。

**根因**：买入理由没有结构化沉淀，卖出动作没有强制对照买入理由做"校验"。

**本工具要解决的是**：把"买入理由"作为持仓的第一等公民字段，**每次卖出（或减仓）必须显式选择卖出动作与买入理由的关系**——是"理由兑现"、"理由证伪"、"理由失效"、还是"无理由违规"。

### 痛点 2：仓位管理没有整体性，每笔交易缺乏对整体仓位的考量

**现象**：
- 加一只票时只看它本身值不值得买，没看加上之后整体仓位变成多少、行业暴露变成多少。
- 没有"整体仓位计划"，仓位是"每一笔交易累加出来的结果"，不是"被设计出来的状态"。
- 系统性风险来临时，才发现仓位早就过高，但已无退路。

**根因**：交易动作发生在标的粒度，但风险发生在组合粒度；缺乏一个"组合视角"的决策入口。

**本工具要解决的是**：
- 给每笔拟执行交易提供 **What-If 整体仓位预览**（买入后总仓位/单标的占比/行业占比如何变化）。
- 给账户设定**整体仓位计划**（目标仓位带、单标的上限、行业上限、现金下限），任何交易先看是否破坏计划。
- 仓位水位要能回答："我当前是不是处于我自己设定好的合理区间？"

### 痛点 3：仓位分散度缺乏理解

**现象**：
- 持仓 8 只票以为很分散，实际可能 5 只都是同一个风险因子（比如都是高 β 成长股）。
- ETF 与个股之间可能存在隐形重叠（如同时持有科创50 和科创半导），实际是同涨同跌。
- 分散度不是"数量多"，而是"风险来源不相关"。

**根因**：缺乏对持仓"风险结构"的透视——按行业、按风格、按相关性切片的视图。

**本工具要解决的是**：
- **多维度分散度切片**：按行业 / 风格（红利/成长/价值/周期）/ 市场（A/港/美）/ 标的相关性聚类，让"看似分散、实则集中"暴露出来。
- **重叠检测**：ETF 持仓与个股之间、ETF 与 ETF 之间的重叠提醒（如持有"科创50 ETF"+"科创半导 ETF"，两者成分股高度重合）。
- **有效分散度指标**：给出"等效独立持仓数"——把高度相关的持仓合并计算，告诉我实际相当于持有了几只不相关的票。

## 四、分层需求清单（重构后）

> 优先级：P0 = 没有就无法解决核心痛点 / P1 = 显著提升日常可用性 / P2 = 锦上添花

### 4.1 痛点1 对应需求：理由闭环追踪

| ID | 需求 | 说明 | 优先级 |
|---|---|---|---|
| R1 | **买入理由结构化记录** | 新建/加仓时必须填写：标的、核心理由（一句话）、理由类型（基本面/技术面/事件/估值/情绪）、预期持有周期、失效条件、目标区间、止损位 | **P0** |
| R2 | **卖出动作强制对照** | 卖出/减仓时必须选择卖出类型：①理由兑现 ②理由证伪 ③理由失效 ④违规卖出（无对应理由）；并填写一句话说明 | **P0** |
| R3 | **理由-交易对账视图** | 每只标的历史上所有"买入-卖出"成对展示，标出理由是否闭环；违规交易单独红色高亮 | **P0** |
| R4 | **违规交易统计** | 按周/月统计"无对应买入理由的卖出"次数、占总交易比例 | P1 |
| R5 | **理由命中率** | 按理由类型统计"兑现/证伪/失效"分布，反哺买入决策质量 | P2 |

### 4.2 痛点2 对应需求：整体仓位管理

| ID | 需求 | 说明 | 优先级 |
|---|---|---|---|
| P1-1 | **仓位计划设定** | 我设定：总仓位目标带（如 60%–80%）、单标的上限（如 25%）、单行业上限（如 30%）、现金下限（如 15%） | **P0** |
| P1-2 | **仓位水位仪表** | 当前仓位 vs 目标带的可视化；超出/低于区间时醒目提示 | **P0** |
| P1-3 | **集中度告警** | 任一维度（单标的/单行业/单风格）超阈，立即在复盘页顶部红色横幅 | **P0** |
| P1-4 | **What-If 交易预演** | 输入拟买入/卖出的标的和金额，实时预演交易后：总仓位、单标的占比、行业占比、是否触发任一告警 | **P0** |
| P1-5 | **系统性风险对照** | 把组合的回撤与同期沪深300 / 创业板指回撤对照，看"我是否比大盘跌得更狠"——这是整体仓位是否合理的最终检验 | P1 |
| P1-6 | **仓位变化时间线** | 历史每日总仓位曲线 + 关键事件标记（加减仓节点） | P1 |

### 4.3 痛点3 对应需求：分散度透视

| ID | 需求 | 说明 | 优先级 |
|---|---|---|---|
| D1 | **行业切片** | 按申万一级行业（A股）/恒生行业（港）分类，显示各行业市值占比 | **P0** |
| D2 | **风格切片** | 我给每只持仓打风格标签（红利/成长/价值/周期/主题），展示风格占比 | **P0** |
| D3 | **市场切片** | A股/港股/美股/现金 占比 | P1 |
| D4 | **ETF 重叠检测** | 持仓内的 ETF 与 ETF、ETF 与个股，按前十大成分股计算重叠度，重叠 >15% 时提醒 | **P0**（因为我持有科创50 + 科创半导，高度重叠） |
| D5 | **等效独立持仓数** | 用相关性矩阵把持仓聚类，给出"实际相当于持有 N 只不相关票"的数字 | P2 |
| D6 | **集中度指标** | HHI（赫芬达尔指数）/ 前3大持仓占比 / 前5大持仓占比 | P1 |

### 4.4 横向支撑：日常复盘闭环

| ID | 需求 | 说明 | 优先级 |
|---|---|---|---|
| S1 | **每日复盘模板（结构化）** | 替代当前自由文本：①今日操作（标的+买卖+理由类型）②盈亏归因（体系内盈亏 vs 体系外盈亏）③仓位水位是否越界 ④明日计划 | **P0** |
| S2 | **盈亏归因到体系** | 把当日每只持仓的盈亏分类为：符合体系预期 / 超出体系预期 / 体系外噪声 | **P0** |
| S3 | **历史复盘检索** | 按日期/标的/理由类型检索历史复盘 | P1 |
| S4 | **每周回顾视图** | 汇总本周：违规交易数、仓位水位曲线、集中度变化、等效分散度变化 | P1 |

## 八、成功判定（这个工具是否成功）

工具上线 1 个月后，用以下 5 条可验证的指标判断成功：

1. **理由覆盖率**：所有未平仓持仓都有完整的买入理由字段（目标 100%）
2. **卖出闭环率**：本月所有卖出动作都有对应的 sell_type 且非"违规"（目标 ≥ 90%）
3. **违规交易次数**：本月违规卖出次数（目标 ≤ 1 次）
4. **仓位在带率**：本月交易日中，仓位落在目标带内的天数占比（目标 ≥ 80%）
5. **系统性风险对照**：若本月大盘跌 >5%，组合回撤 ≤ 大盘回撤 × 1.2（目标达成）

若 5 条全部达成，说明工具真正在帮我执行交易体系；若有任意一条长期不达标，工具本身需要迭代，而不是"用得不够勤"。

## 九、不在本工具范围内（明确排除）

以下功能**明确不做**，避免工具变形：

- ✗ 实时行情（这是券商 App 的职责，每日手动录入收盘价即可）
- ✗ AI 荐股 / 买卖建议（违背"体系内化"目标）
- ✗ 社区 / 分享 / 抄作业（个人工具）
- ✗ 多用户 / 账户体系（只有自己用）
- ✗ 复杂回测 / 蒙特卡洛 / 因子分析（超出当前痛点的范围）
- ✗ 税务 / 分红 / 多币种（当前用不到）
- ✗ 一键下单（与"复盘工具"定位冲突）
